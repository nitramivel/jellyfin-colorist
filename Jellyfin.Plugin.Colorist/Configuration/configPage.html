Colorist

Samples colour across every movie and episode with ffmpeg, reduces each sampled frame to one representative colour, and draws the sequence as a vertical-stripe barcode across the foot of the detail page.

Median cut groups each frame's colours into boxes and picks one — fast, repeatable, and the sensible default. k-means finds better-shaped groups on graded footage such as sunsets, at roughly thirty times the cost. Average is the naive one: it tends to brown, because a red coat against green leaves genuinely averages to mud. It is here to compare against.
How much a colour's share of the frame counts against how vivid it is. 0.0 ignores area entirely and picks the most vivid patch, so one pixel of lens flare decides the stripe. Raising it tilts towards area; around 1.5 and above a large dull background starts winning over a small bright subject. 0.6 lets a small bright subject beat a large grey wall without letting a speck beat the subject.
Too few blends distinct colours together; too many split one real colour across several groups and weaken each. 8 is a good default.
Pixels darker than this are ignored when choosing a colour. Mops up letterbox bars that survived cropping, and lets a night scene lit by one lamp read as the lamp. Frames with nothing above the floor still come out black.
A fixed count, not a fixed interval — so a 22-minute episode and a 3-hour film produce comparable images, and each costs about the same to make. Short items automatically get fewer stripes rather than sampling the same second twice.
Asks the decoder to skip rebuilding the frames in between, which can be much faster. It is only a hint, though — some decoders and some files ignore it entirely and hand over every frame anyway, so treat any speed-up as a bonus rather than a promise. Either way the number of frames actually analysed is capped at the stripe count above, so leaving this on never costs you anything.
Leave this on. An HDR file decoded as though it were SDR reads far too dark and far too grey, so every 4K HDR title produces a muted strip that looks nothing like the film. Dolby Vision profile 5 is worse — with no HDR10 base layer it decodes pink and green — and is converted with libplacebo so the Dolby Vision metadata is actually applied. Profiles 7 and 8 carry a normal HDR10 base and go through the standard path. If the required filter is missing from your ffmpeg, Colorist falls back a step at a time and says so in the log rather than producing nothing.
Black bars wash out every sample, so they are removed before the colour is measured. Auto probes each file a third of the way in — never at the start, where a fade from black would suggest cropping away the entire picture — and takes the reading the file agreed on most often. Any crop discarding more than 40% of an axis is rejected as implausible.
Credits are real footage, so the sampler will faithfully report five minutes of black as a black tail on every image. Trimming a percentage of the runtime is deliberately blunt: detecting black runs instead misfires on films that are genuinely dark, and quietly deleting the last eight minutes of one is worse than keeping some credits.
Fades one stripe into the next instead of hard edges. Blending is done perceptually, so transitions do not pass through a dark seam the way naive blending does. Takes effect on the next page load — nothing needs regenerating.
Writes <video filename>-colorist.json into the movie folder, or the season folder for episodes. The -colorist suffix is not one Jellyfin's scanner recognises, so nothing here will ever be adopted as the item's poster or thumbnail. If the folder is read-only — common for bind mounts — the file goes to the plugin's data directory instead and the barcode still displays normally.
Off by default, and nothing in Jellyfin reads it. A barcode is stored as the colours that were measured, which is what the detail page draws — that is why the height and the blending above cost a page reload rather than another run of ffmpeg across the library. Switch this on if you want <video filename>-colorist.png in the folder for something else to open; unlike the colour data, its size and blending are fixed at whatever they were when it was written. Switching it off removes the PNGs as items are regenerated.
Only used when the PNG is switched on. The strip on the detail page is drawn at the window's width and the display height below, whatever these say.
How tall the strip is at the foot of the page. It always spans the full width edge to edge, whatever the window size, so this is the only dimension worth setting. Around 60–120 reads as a band under the page; 200 and up reads as a feature. Takes effect on the next page load, not just the next restart.
Off by default, so a run picks up only what is new. Turn it on after changing the colour algorithm or the trims, or the existing images will never be revisited.
Auto uses a quarter of the processors. Colorist also runs every ffmpeg at below-normal priority, so a viewer starting a transcode mid-run takes CPU back from the barcode job rather than queueing behind it.
Generate now
Queues the scheduled task. A full library is potentially hours of ffmpeg, so it runs in the background — watch it under Dashboard → Scheduled Tasks.
Try one item
Paste an item ID to build a single barcode with the current settings and see the result. Faster than running the library to find out whether you like the algorithm.
Delete saved barcodes
Removes what Colorist has written, from the library folders and from the plugin's data directory, across every movie and episode — including ones the include switches above currently exclude. Runs as a background task; watch it under Dashboard → Scheduled Tasks. Read-only folders are reported in the log and skipped.
On by default, and the safe choice. The colours are what the detail page draws and they cost hours of ffmpeg to rebuild; the PNGs are an optional extra nothing in Jellyfin reads. Clear this to remove everything and start over — every barcode will need sampling again.
